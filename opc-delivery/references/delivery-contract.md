本文件定义 opc-delivery 中 MasterGo 子流程的交付边界。每条路径都必须先确认用户要的真实成果,
再检查完成该成果所需的 MCP、数据和用户动作。缺关键能力时是阻塞,不是换个产物交差。

---

## 总原则

- 路由决定交付物,不能把 A 路径的半成品包装成 B 路径的完成;
- 缺 MCP / token / layerId / contentId / 接口文档 / 用户截图 / 后端时,按对应流程阻塞,
  不降级成交付文档、提示词、截图或静态 mock;
- 中间产物可以创建,但必须标注为"中间产物 / 待推送 / 待验证",不能说完成;
- 设计路径还必须满足 UI 文案语种契约;页面语言错误不能包装成"已完成";
- 只有用户明确改口要求中间产物本身,才把它当本轮交付。

## 专业完成定义

专业交付完成不是“我做了很多事”,而是以下证据闭合:

| 维度 | 完成证据 |
|---|---|
| 业务目标 | PRD 或轻量 PRD 写明 Core Job、Must 范围、成功指标和验收标准 |
| 方案合理性 | Solution 说明候选方案、推荐原因、放弃方案、风险和下游输入 |
| UI/体验 | 覆盖核心角色、流程、关键状态、语种、可访问性和错误恢复 |
| 工程实现 | 代码遵循现有项目约定,核心交互可运行,API/mock 切换边界清楚 |
| 验证 | lint/typecheck/test/build/Browser/截图中可运行项已执行并读过输出 |
| 发布 | preview 或 production URL、环境变量位置、健康检查、核心流程和回滚方式明确 |
| 风险 | open questions、blocked/skipped 项、premortem/red-team/stop conditions 按阶段记录 |
| 校准 | 已上线回放时有 gap report、AAR 和规则/eval/script 更新 |

任一维度缺证据时,只能说该维度 `pending`、`blocked` 或 `skipped with reason`。
不要把工作量、文件数量、命令成功或主观满意替代专业完成证据。

## 需求覆盖

交付物不仅要类型正确,还要覆盖用户需求。设计任务开始前按
[design-scope.md](design-scope.md) 建立覆盖 brief:

- 不根据关键词机械决定单页 / 多页;
- 不把完整需求擅自缩成首页、首屏或概念代表页;
- 低置信时用选择题澄清范围,最后保留"自定义 / type something";
- 配置 / 重启 / reconnect 后继续任务时,先恢复原始目标和覆盖 brief。
- 页面 UI 文案语种按 [copy-language.md](copy-language.md) 判断;中文聊天或中文素材
  默认简体中文 UI,保留必要英文技术名词。

## 交付物矩阵

| 用户意图 | 路径 | 真正交付物 | 不算完成 |
|---|---|---|---|
| 在 MasterGo 上设计 / 修改 | Codify | 覆盖 brief 已闭合 + UI 文案语种正确 + MasterGo 画布已写入 + 3A 验证 | 本地 HTML、Markdown 方案、截图、Codify prompt、一个未确认范围的代表页、未授权英文 UI |
| 把 MasterGo 还原成代码 | Magic | 本地前端项目已实现 + 3B 验证 | 只拉到 DSL/D2C、只保存资源、只起 dev server |
| 设计稿更新了,同步代码 | Magic update | diff 已应用到目标代码 + 3B 复验 | 只输出 diff 报告、只重拉 D2C |
| 看 MasterGo 文件 / 页面结构 | Codify/Magic | 来自真实工具调用的页面 / 节点 / DSL 摘要 | 凭想象总结、泛化产品建议 |
| 配置 MasterGo/Codify MCP | setup | 当前宿主配置文件写入 + 重启/工具状态验证 | 只给安装建议、只发现其它宿主已有配置 |
| 企业级实现接 API | API wiring | 字段映射 + 数据层 + API 溯源汇报 + 3B-2 验证 | 假数据、未接 API 但说生产可用 |

## 能力缺失时

缺能力时按"最接近真实交付物"的阻塞点处理:

- 缺 Codify 写入能力 → 回 [mcp-setup.md](mcp-setup.md),不做本地设计替代稿;
- 缺 Magic 读取能力 → 回 [mcp-setup.md](mcp-setup.md),不凭截图或口述手写还原;
- 缺需求范围或无法判断覆盖口径 → 按 [design-scope.md](design-scope.md) 用选择题澄清;
- 缺 `layer_id` → 让用户在 MasterGo 选中目标 Frame 后重发链接;
- 缺 D2C `contentId` 数据 → 让用户点"发送数据",再重拉;
- 缺 API 文档 → 标记企业级实现"未接 API",不能说生产级完成;
- 缺截图 / 浏览器验证 → 标记"待视觉验证",不能说完成。

---

## 禁止替代交付

除非用户明确改口,以下都不能替代 MasterGo 路径的真实交付物:

- 新建 `docs/*.md` 设计蓝图;
- 生成本地 HTML / React 静态原型;
- 只给一段可复制到 Codify 的 prompt;
- 页面主要 UI 文案未按用户语种生成,却声称设计完成;
- 改用 Figma / 图片 / Mermaid;
- 只输出 DSL / D2C / diff 报告;
- 只报告 HTTP 200、构建成功、文件存在。

如果需要这些作为中间产物,回复必须带状态词:`中间稿`、`待推送`、`待配置`、
`待用户动作` 或 `待验证`。

## 完成话术

允许:

- "已推送到 MasterGo,`get_design_diff` 与截图验证通过。"
- "还原项目已跑通,3B 截图验证和 API 溯源汇报已通过。"
- "配置已写入当前宿主,重启后工具已连通。"

禁止:

- "本地文档已完成 MasterGo 设计稿。"
- "D2C 拉下来了,还原完成。"
- "HTTP 200,完成。"
- "工具不可用,我先给你 prompt,完成。"
