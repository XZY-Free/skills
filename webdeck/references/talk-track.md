# 配套讲稿（口播稿）

有人现场讲的 deck（培训、汇报），除了页面，再配一份讲师照着念的**口播稿**：一个独立的 `.md`，和幻灯片**逐页对应**，里面就是**要讲出来的话**，不放计时、提示、录屏兜底那些东西。

讲稿是 deck 之外单独的一份文件——**deck 里不再内嵌讲师备注**，省得两处漂移、一处一个版本。

## 什么时候生成

- **有人现场讲**（培训、汇报、宣讲）→ 默认生成讲稿。
- **纯自己看的**（产品介绍页、对外分享页，没人念稿）→ 不生成。

拿不准就问一句「这个要不要配讲稿」。

## 格式

逐页一段，纯口播台词：

```
### 第 X 页 · 标题

这一页要讲的话，一整段大白话，对应幻灯片这一页。

### 第 X+1 页 · 标题

下一页要讲的话。
```

只有要念的话，不夹方括号提示、不标时间。一页一段，和幻灯片页码对齐。

## 口播稿的去 AI 味，比页面文案狠一层

页面文案的判断（[anti-ai-flavor.md](anti-ai-flavor.md)）讲稿全都适用。但「念出来的话」还多几条，而且**特别容易栽**——下面这些是反复踩过的坑：

**1. 润色 ≠ 重构（最容易栽的一条）。** 在原句上换几个词、句子结构没动，腔调就还在——这只是润色，AI 味原封不动。去 AI 味要的是**重构**：把整段推倒，用人话重讲一遍。
> 自检：如果你只是把几个词换得更口语、骨架没动，那就是在润色，停下，推倒重讲。

**2. 作文骨架本身就是 AI 味的根。** 「先点题 → 两块对称分述、各配一个精巧类比 → 末尾工整总结」——这套结构换词没用，结构在味儿就在。真人讲话是**松的**：想到哪说到哪、两块讲得不一样长、讲完就完，不每段都配个类比，不末了来个总结。重构就是把这套骨架拆了。

**3. 别蹦金句。** 句句恰到好处、动不动来个巧妙比喻或成语，本身就是 AI 味——真人脱口而出不长这样。**真人是松的、会啰嗦、会重复、不蹦金句。**

**4. 但别矫枉过正成磕巴。** 满嘴「啊/么」、「这个就是……」那种语塞，是另一种假。落点是**流畅平实的大白话**：句子是顺的、完整的，不堆语气词，不磕巴也不蹦词，平平稳稳把事说清楚。

**5. 口播专属的几类 AI 味：**
- **提示腔**——「记一句就行」「大家先记着」「记住了上手能快不少」。
- **替听众安排的旁白**——「我先点一下授权，等会儿讲到 X 再展开」。直接删，讲的时候自然会带。
- **工整排比 / 对仗 / 等长两拍**——念出来尤其明显。

> **上屏和口播是两种语域。** 屏幕上的标语可以对仗（给眼睛看、好记）；同样的对仗**念出来**就是 AI 味。所以页面上的 punch 句和讲稿台词不必一致，各按各的来。

## 现场校准：怎么定那个「对的声音」

别想着一次写对全篇。口播稿对不对，是**用户的耳朵**说了算，不是规则说了算。所以：

1. 先写两三页讲稿；
2. 给用户看，听他的反应；
3. 用户一反应，那个「对的声音」就定住了——已经认可的页就是**基准**；
4. 后面所有页都照这个基准的劲儿写，不再凭空猜。

这是讲稿去 AI 味唯一可靠的办法。前面认可的页就是标尺，后面对着它写。

## 和页面保持同步

- **页面内容一改，对应那页讲稿跟着改**，反过来也一样。一份 deck 两个文件，别让它们说不同的话。
- **当心跨页回扣。** 讲稿里「刚才说的……」「前面那个……」指的是前面某一页；那页内容一换，这句回扣就接不上了，得跟着修——否则听众一愣：刚才说啥了？

## 产品 / 事实别编

讲稿里涉及某个功能是什么、某个操作怎么点，跟页面一样，**从真实来源核**（`curl` 官方文档），编错了讲出去就是事故。
