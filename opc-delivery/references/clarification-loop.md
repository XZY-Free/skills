# 高影响疑点澄清循环

目标: 不懂时不要假设; 但也不要把内部阶段卡、确认卡变成用户必须消费的流程。用户只关心成品、关键选择和证据。

OPC 的澄清模型是**成品驱动 + 疑点触发确认**:

- 需求足够明确时, 直接产出 PRD、方案、代码、验证和部署证据;
- 低风险工程细节由代理自治处理;
- 只有会改变最终成品、成本、安全或发布路径的不确定项才打断用户;
- 阶段卡、确认卡、8 阶段表、raw `summary` / `resume` 只作为内部记录写入 `.opc/`, 不作为每阶段固定展示。

执行阶段(implementation / verification / deployment / calibration)默认自治推进, 见各自 reference。`implementation-plan` 是实现前规划门禁, 默认自动产出上下文索引和用户价值切片。

## 核心心智模型

错误模型:

```text
每个阶段都给用户一张卡 -> 等用户回 -> 再给下一张卡 -> 用户被流程拖住
```

正确模型:

```text
用户给目标
  -> AI 内部拆范围、默认值和风险
  -> 没有高影响疑点: 直接推进成品
  -> 有高影响疑点: 打开原生选择交互
  -> 用户提交后继续推进
  -> 产出 PRD / 方案 / 代码 / 验证 / 部署证据
```

内部阶段卡和确认卡的作用:

- 保存当前理解、默认假设、用户提交结果和下一步;
- 支持断线恢复;
- 让 `handoff-lint.py`、`opc-task-state.py` 和 eval 能验证行为;
- 不把“每阶段至少一轮”强加给用户。

## 什么时候必须问

满足下面任一条件, 且本地上下文无法可靠推断时, 必须用宿主原生选择/确认交互:

| 类目 | 示例 | 为什么高影响 |
|---|---|---|
| 数据真实性 | 真实接入 / 演示数据 / 用户上传 CSV | 决定是否需要后端、数据库和验收口径 |
| 范围承诺 | “企业级”“完整”“生产级”“智能”“后台”具体含什么 | 直接改变模块数量和验收标准 |
| 权限与合规 | RBAC、SSO、审计、客户数据、SLA、品牌硬约束 | 涉及安全、法务和信任 |
| 部署路径 | 本地预览、Vercel、Cloudflare、自有服务器、production | 决定凭证、成本和回滚 |
| 账号与密钥 | API key、token、secret、私有 URL、服务器地址 | 代理不能代造或写入仓库 |
| 副作用 | 远端 push、覆盖画布、覆盖服务器/数据库、破坏性迁移 | 不可逆或影响协作者 |
| 付费资源 | 采购、开通云服务、升配 | 涉及真实成本 |

用户说“你决定”时, 若属于高影响项, 仍要给推荐默认和理由; 宿主支持原生交互时打开确认框。用户明确授权默认项后继续。

## 什么时候不要问

下面事项默认自治, 记录在内部日志或收尾的“我已自治处理”里即可:

- 文件名、目录名、组件拆分、helper 拆法;
- 小依赖选择, 例如图标库、日期格式化库;
- 本地脚手架、`.gitignore`、`.env.example`、测试命令;
- 内部路由、mock seed 的具体值、单文件代码组织;
- 可逆默认值, 例如分页大小、默认排序、按钮文案微调;
- 已被用户、PRD、方案或现有代码明确锁定的事项。

不要为了显得严谨把这些问题推回给用户。

## 宿主原生交互

需要用户拍板时, 先使用当前宿主真实结构化交互:

1. Codex App 可用 `request_user_input` 时, 调用真实选择框;
2. Claude Code 或其它 runner 暴露 confirm/select/prompt 时, 用对应工具;
3. OMX question bridge 或等价 native UI 可用时, 用桥接选择;
4. 上述都不可用时, 才在文本里降级为 A/B/C/D。

使用原生交互时:

- 每轮 1-3 个问题, 每题 2-3 个互斥选项;
- 推荐项放第一并标 `(Recommended)` 或宿主等价标记;
- 保留 Other / 自定义入口, 或在说明里写明“选择框含自定义入口”;
- 普通聊天文本只写“已打开原生交互、默认推荐、等你提交后继续”, 不复制一整套长问卷。

文本降级格式:

```text
[需要你拍板]
- A. <推荐默认> — <一句理由>
- B. <备选> — <一句影响>
- C. <备选> — <一句影响>
- D. 自定义 / type something
- 默认 = A

[下一步]
等你回 A/B/C/D 后继续。
```

降级时必须说明原因: 当前宿主没有可用结构化交互、当前模式不允许调用, 或运行面没有 question bridge。

## 内部确认卡记录

需要澄清时, 内部记录可以写成:

```text
OPC Internal ConfirmCard · <phase> · <yyyy-MM-dd HH:mm>

[当前理解]
- 业务目标:
- 用户 framing 翻译:
- 已锁定事实:

[我默认处理]
- 低风险默认:
- 理由:

[需要用户拍板]
- 问题:
- 推荐:
- 备选:
- 交互面: request_user_input / confirm-select / 文本降级
- 用户提交:

[收敛判断]
- 可继续:
- 下一步:
```

注意: 这张卡可以写入 `.opc/<phase>/discussion.md`, 但不必完整贴给用户。用户只看必要摘要和选择交互。

## 用户可见输出

进度类问题默认输出结果摘要, 不展示内部阶段表:

```text
目标: <用户目标>
已交付: <普通话术摘要>
正在推进: <普通话术摘要>
需要你做什么: <无需操作 / 等选择 / 卡住缺 X>
接下来: <下一步动作>
```

有高影响疑点时, 用户可见输出保持短:

```text
[已完成]
- 我已把“企业级用户中心”拆成账号、登录、角色、权限、审计和导出几类交付范围。

[证据]
- 内部澄清记录: .opc/requirements/discussion.md

[需要你拍板]
- 已打开原生选择框: 权限深度
- 推荐默认 = 基础 RBAC + 审计日志, 因为它覆盖企业后台最常见验收。
- 选择框含自定义入口。

[下一步]
等你在原生交互提交后, 我把结果写入 PRD 并继续方案设计。
```

无高影响疑点时, 用户可见输出应直接推进:

```text
[已完成]
- 我已从你的需求里抽出目标、角色、核心流程和验收口径。

[证据]
- PRD: .opc/requirements/prd.md
- 状态台账: .opc/state/opc-task.json

[不确定项 + 我的处理]
- 没有未决项。文件名、目录和本地脚手架我按项目现有风格自治处理。

[下一步]
我现在进入方案设计并补齐接口、数据和部署计划。
```

## 讨论日志规约

每个定义阶段维护 `.opc/<phase>/discussion.md`。追加模式, 不覆盖。

```markdown
# <phase> Discussion Log

## Entry <N> — <yyyy-MM-dd HH:mm UTC>

### 来源
- 用户输入 / 现有 PRD / 代码 / 接口文档 / 截图:

### 内部理解
- 业务目标:
- 用户 framing 翻译:
- 已锁定事实:
- 低风险默认及理由:

### 高影响不确定
- 是否存在: yes/no
- 需要拍板的问题:
- 交互面: request_user_input / confirm-select / OMX question bridge / 文本降级
- 推荐默认:
- 用户提交结果:

### 决策结果
- 确定:
- 自治处理:
- 仍卡住:

### 下一步
- 写 PRD / 写方案 / 进入实现 / 等用户在原生交互提交 / 卡住缺 X:
```

PRD、方案和 UI Brief 只写收敛结论, 不塞长讨论纪要。

## 推进与收敛判断

可以继续推进的信号:

- 高影响不确定不存在, 或已通过用户原话、已有资料、原生交互提交、文本降级回复解决;
- 用户 framing 已翻译成具体范围, 不再影响本阶段产物;
- PRD / 方案 / UI Brief 能落成可执行验收标准;
- 上一轮提交没有引出新的高影响不确定。

AI 自动执行:

1. 写阶段产物;
2. 更新 `.opc/<phase>/discussion.md`;
3. 写 `.opc/<phase>/last-handoff.md`;
4. 跑 `scripts/handoff-lint.py`;
5. `opc-task-state.py mark <phase> done`;
6. 进入下一阶段。

不要求用户说“继续”。

## 反模式

- 把阶段卡或确认卡当成用户侧固定流程。
- 默认展示“阶段进度(OPC 8 阶段)”表、box-drawing 表格、raw phase IDs 或 artifact/evidence/nextAction。
- 每个定义阶段都强制至少一轮用户确认。
- 需求清楚时仍停下问“是否继续”。
- 低风险工程细节让用户拍板。
- 高影响不确定不问, 私自猜完再写进 PRD。
- 当前宿主明明能打开选择框, 仍要求用户手敲 A/B/C。
- 文本降级不给默认项或自定义入口。
- 一轮塞 5 个以上问题, 把选择交互变成长问卷。
- 收尾只列“剩余风险”, 没有行动、默认、阻塞分类或下一步。
