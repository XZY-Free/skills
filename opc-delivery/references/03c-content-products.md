# 03c — 内容消费类品类骨架

服务于"内容消费"主姿态的产品。用户主任务是**消费连续内容流**: 读 / 看 / 听 / 刷, 而不是配置、管理或处理事务。

## 何时读

- 方案阶段产品姿态判断 = 内容消费(主姿态)
- 不确定子类型属于 reading / video / feed / audio
- 写竞品调研 / 首屏主信号 / 升降级表时, 需要品类默认参考

跳过场景: 主姿态不是内容消费; 学习材料带强进度感的归学习产品姿态独立处理。

## 内容消费类共通特征

### 主任务

连续消费内容(读 / 看 / 听 / 刷), 反复回来。不是单次任务后离开。

### 默认 IA 骨架

| 层级 | 默认内容 |
|---|---|
| 首屏主信号 | "上次未完成位置 + 推荐流" 双信号; 内容主体 ≥ 60% 视觉权重 |
| 一级导航 | ≤ 3-4 项: 推荐(发现) / 我的(书架/收藏) / 搜索 / 个人(账号) |
| 二级 | 分类、标签、播放历史、笔记、下载 |
| 设置 | 偏好、隐私、通知、订阅管理 |

### 升降级默认

| 能力 | 默认层级 | 理由 |
|---|---|---|
| 主内容浏览 / 阅读器 / 播放器 | 高曝光 | 主任务 |
| 推荐 / 发现 | 高曝光 | 找新内容 = 主任务的另一面 |
| 个人内容(书架/收藏/历史) | 高曝光 | 回到上次 = 高频路径 |
| 搜索 | 中曝光(顶部固定栏) | 有需求时再用, 不抢主位 |
| 标签 / 分类 | 中曝光 | 二级导航或筛选 |
| 笔记 / 划线 / 评论 | 仅上下文 | 阅读中产生, 不独立页 |
| 分享 | 仅上下文 | 内容详情里的 action |
| 订阅管理 | 低曝光 | 设置子项 |
| 偏好 / 隐私 | 低曝光 | 设置 |
| 账号 / 充值 / 会员 | 低曝光 | 用户菜单 |

### 共通首屏主信号写法

```
用户首屏第一眼看到:
- 主区(60%+ 视觉权重): <上次未完成位置 / 当前正在消费的内容>
- 次区(25-30%): <发现 / 推荐 / 新内容信号>
- 边缘(<10%): 导航 / 账号入口 / 搜索按钮

绝对不放在首屏的:
- 数据看板 / KPI 卡 / 阅读时长统计
- 营销 hero + CTA
- 设置入口 / 账号管理 / 订阅状态
```

## 子类型: Reading

例: 微信读书 / Kindle Web / Substack / Medium / 多看 / 得到 App

### 主姿态特征
- 内容形态: 长文本(书 / 文章 / newsletter)
- 单次会话长度: 较长(15+ 分钟)
- 用户期待: 沉浸、可恢复进度、可标注

### 默认 IA

```
一级导航: 书架 / 发现 / (搜索) / 我
首屏:    [上次未读卡片占首屏 50%]
        [发现/推荐书架占 30%]
        [底部 tab 导航 ≤ 4 项]

阅读器:
- 全屏沉浸, 工具栏自动隐藏
- 划线 / 笔记 / 字体设置 = 仅上下文(长按或上拉)
- 章节目录 = 抽屉
- 上一页 / 下一页 = 手势或边缘点击
```

### 升降级默认

| 能力 | 层级 | 位置 |
|---|---|---|
| 阅读器 | 高曝光 | 主体 |
| 书架 / 收藏 | 高曝光 | 一级 tab |
| 发现 / 推荐 | 高曝光 | 一级 tab |
| 搜索 | 中曝光 | 顶部按钮 |
| 笔记 / 划线 | 仅上下文 | 阅读器内长按 |
| 字体 / 排版设置 | 仅上下文 | 阅读器内顶部 |
| 听书模式 | 中曝光 | 阅读器内切换 |
| 阅读时长 / 数据 | 低曝光 | 我 > 详情 |
| 朋友圈 / 社交 | 中-低曝光 | 我 > 子项, 不抢 tab |
| 充值 / 会员 | 低曝光 | 我 > 子项 |

### 反模式
- 把"阅读时长 / 已读多少本"放首屏(把消费做成 KPI 后台)
- 一级导航摆 6 个: 书架 / 发现 / 故事 / 听书 / 社区 / 我 (用户嫌乱)
- 阅读器外加大量装饰 / hero 区

## 子类型: Video

例: YouTube / Bilibili / TikTok / Netflix

### 主姿态特征
- 内容形态: 视频
- 单次会话长度: 视情况(短视频 30s / 长视频 30+ 分钟)
- 用户期待: 流畅、可推荐、可恢复

### 默认 IA

**长视频** (YouTube / Netflix):
```
一级导航: 推荐(首页) / 订阅 / 我(library)
首屏:    [大封面推荐区 + 多排推荐流]
播放器:  全屏 / 嵌入 / 画中画
```

**短视频** (TikTok / 抖音):
```
一级导航: For You / 关注 / 发现 / 我
首屏:    [全屏单一视频 + 右侧 action 列(点赞/评论/分享/收藏)]
导航:    手势上下滑 = 切换
```

### 升降级默认

| 能力 | 长视频层级 | 短视频层级 |
|---|---|---|
| 播放器 | 高曝光 | 高曝光(全屏) |
| 推荐流 / For You | 高曝光 | 高曝光(就是首屏) |
| 订阅 / 关注 | 高曝光 | 高曝光 |
| 搜索 | 中曝光 | 中曝光 |
| 点赞 / 收藏 / 分享 | 仅上下文 | 仅上下文(右侧栏) |
| 评论 | 仅上下文(详情下方) | 仅上下文(右下角) |
| 历史 | 中曝光(我之下) | 中曝光 |
| 创作 / 上传 | 高/中曝光(看产品定位) | 高曝光(底部 + 号) |
| 设置 / 数据 | 低曝光 | 低曝光 |

### 反模式
- 短视频产品摆 5 个底部 tab, For You 不是默认
- 长视频首屏放"播放数据看板"
- 把"上传中心"当一级 nav 而不是用户菜单子项

## 子类型: Feed

例: Twitter / 小红书 / 微博 / Reddit / 即刻

### 主姿态特征
- 内容形态: 短帖子 / 图片 / 短文混合
- 单次会话长度: 短(5-15 分钟, 但频繁)
- 用户期待: 时间线 / 推荐 / 互动

### 默认 IA

```
一级导航: 首页(timeline) / 发现 / 通知 / 我
首屏:    [timeline 主体占 70%+]
        [发布按钮 浮动或底部固定]
顶部:    搜索 / 切换"关注/推荐"
```

### 升降级默认

| 能力 | 层级 |
|---|---|
| Timeline / Feed | 高曝光(首页) |
| 发布 | 高曝光(浮动 + 按钮) |
| 发现 / 推荐 | 高曝光(一级 tab) |
| 通知 | 高曝光(顶部图标 + 一级 tab) |
| 搜索 | 中曝光(顶部) |
| 点赞 / 评论 / 转发 | 仅上下文 |
| 个人主页 / 关注 / 粉丝 | 中曝光(我 > 子项) |
| 设置 / 隐私 | 低曝光 |
| 私信 | 中曝光(独立入口或一级 tab) |

### 反模式
- 首页不是 timeline, 而是"热榜 / 话题 / 推荐 / 数据"四象限
- 发布按钮藏得很深(在二级菜单里)
- 通知没有红点 / 数字, 用户不知道有未读

## 子类型: Audio

例: 播客 (Apple Podcasts / 小宇宙) / 听书 (得到 App 音频) / 音乐 (Spotify / 网易云)

### 主姿态特征
- 内容形态: 音频
- 单次会话长度: 中-长(10-60 分钟)
- 用户期待: 后台播放 / 可恢复 / 队列管理

### 默认 IA

```
一级导航: 推荐 / 我的(订阅+下载) / 搜索 / (我)
首屏:    [上次播放卡片 + 推荐]
固定:    [底部播放条 — 整个 app 都看得到]
```

### 升降级默认

| 能力 | 层级 |
|---|---|
| 播放器(底部条 + 全屏播放) | 高曝光(底部条全 app 可见) |
| 推荐 / 发现 | 高曝光(一级 tab) |
| 我的订阅 / 下载 | 高曝光(一级 tab) |
| 搜索 | 中曝光(顶部) |
| 队列 / 历史 | 中曝光(播放器抽屉) |
| 倍速 / 定时关闭 | 仅上下文(播放器内) |
| 收藏 / 喜欢 | 仅上下文 |
| 评论 / 笔记 | 仅上下文(详情下方) |
| 数据 / 统计 | 低曝光(我 > 子项) |
| 充值 / 会员 | 低曝光 |

### 反模式
- 底部播放条不全 app 持久(切 tab 就消失)
- 倍速 / 定时 / 音质抢一级导航位
- 首屏摆"今日热度榜"而不是"上次播放"

## 品类反模式

跨子类型共通的反模式, 3C 验收时逐项扫:

- **首屏放数据看板**: 阅读时长 / 播放历史统计 / 用户行为指标 — 这是后台思维, 不是消费产品
- **一级导航超过 4 项**: 内容消费类用户来"消费", 不来"管理", 5+ 项必是工程模块翻译
- **设置 / 账号 / 充值进一级导航**: 应在用户菜单子项, 不抢主位
- **内容主体小于 50% 视觉权重**: 主体被装饰、推荐、广告挤压 = 把消费做成了管理
- **没有"上次未完成"信号**: 用户每次来都从零开始, 没有连续性
- **搜索抢首屏主位**: 搜索应是中曝光顶部按钮; 主位让给内容
- **创作 / 上传在非 UGC 产品做成一级 tab**: 看产品定位; 微信读书没创作, TikTok 有创作(本身是 UGC)
- **多子类型混搭做成多 tab 互不相干**: 听书+阅读+社区 = 姿态混乱, 应选一个主姿态

## 用法接入

### 方案阶段

读本文件 + [03b-productization.md](03b-productization.md) → 在 `.opc/solution/solution-design.md` 写:

1. **产品姿态判断**: 主姿态 = 内容消费, 子类型 = reading / video / feed / audio
2. **竞品调研**: 选 2-3 个本子类型的成熟产品(本文件每节已列示例)
3. **首屏主信号**: 用本品类的"共通首屏主信号写法"模板, 不要写口号
4. **能力升降级表**: 以本子类型的"升降级默认"为起点, 按 PRD 调整

### 验证阶段

3C 对账时, 用本文件的"品类反模式"清单和子类型示例做对照。

### 注意

本文件的"升降级默认"是参考起点, 不是结论。具体 PRD 可能要求微调, 但偏离默认时要在 solution-design 写理由(便于 3C 对账)。
