# 单文件 HTML 演示稿：引擎层

这页讲「引擎」——翻页、字体、离线、投屏尺寸这些**每份 deck 都一样、枯燥又容易写错**的底层。直接用脚手架 [../assets/deck-scaffold.html](../assets/deck-scaffold.html)，复制了改，别每次从零写。

**引擎可以固定，长相不能固定。** 谁也看不出两份 deck 都用方向键翻页就说它们是模板套的；但两份 deck 配色版式一样，一眼就露馅。所以脚手架只给引擎和骨架，里面的颜色/版式是中性占位，**每份现设计**（审美交给 frontend-design 那套）。

## 为什么是「单文件、离线」

整份 deck 是一个 `.html`，CSS/JS 都内联，双击就放映，不连网也行。理由：

- **现场最稳**。投屏的电脑网络环境五花八门，任何外部依赖（CDN 字体、在线图床、远程脚本）都可能在现场加载失败，让页面变难看甚至白板。
- **好交付**。发一个文件就完事，对方不用装环境。
- 代价：图片要么内联，要么走部署后的同源路径（见下面「图片别用 base64」）。

## 关键设计，和为什么

**字体用系统中文字体栈**，不引外部字体：
```
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif
```
Mac 上是苹方、Windows 上是雅黑，都干净。引外部中文字体动辄几 MB，现场加载失败就难看——不值。

**按 16:9 投屏比例排版**，自检也按 `1440×810` 截图。投影仪基本都是 16:9，一页一屏铺满，别让内容超出一屏要滚动。

**点击页面【不】翻页。** 只用键盘（← → / 空格 / Home / End）和左下角按钮翻。原因：现场想选段文字、或者误触，整个画面乱跳很尴尬。（脚手架默认就是这样——别手贱加回 `click→翻页`。）

**入场动画**：元素加 `data-r` 和 `style="--r:0"`（0/1/2…按出现顺序），切到该页时按序淡入上移。克制用，别每个字都动。

## 不内嵌讲师备注，讲稿单独成文

脚手架**不带**页面内嵌的讲师备注。现场要念的台词，放在一份单独的讲稿 `.md` 里（逐页对应，见 [talk-track.md](talk-track.md)）——一个源头，省得「页面里一版、讲稿里一版」两处漂移。

计时器（按 `T`）留着，对现场控时有用，它和备注是两回事。

> 为什么不内嵌：演示稿和讲稿是两份东西、改的节奏也不一样；硬塞进同一个 HTML，一边改了另一边容易忘。分开反而清楚。

## 图片别用 base64，走部署后的路径

图省事把图片 base64 内联进 HTML，会把文件撑得很大（一张名片图能让 HTML 从 46KB 涨到 148KB）、图和代码混在一起难维护。

**做法**：图片上传到服务器，HTML 里用同源路径引用（比如 `/plans/xxx.jpg`）。这样 HTML 保持小而干净。注意：用了绝对路径引用后，本地 `file://` 打开会看不到图，**自检得截线上**。具体见 [self-check-and-deploy.md](self-check-and-deploy.md)。

> 二维码这种关键图，jpg 压缩可能影响扫描——让本人或用户拿手机实扫一次确认，你没法替他验证码能不能用。

## 改完顺手清孤儿 CSS

改版式经常留下没人用的 CSS（上一版的卡片样式、布局类）。改完用 `grep` 查一下某个 class 在 HTML 里被引用几次，0 次的就删掉。留着不影响显示，但越积越乱，下次更难改。
