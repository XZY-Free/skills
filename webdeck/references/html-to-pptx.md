# HTML 成品转可编辑 PPT

主力交付是 HTML。但有时用户要一份**可编辑的 `.pptx`**（要拿去公司模板里改、要发给不方便开网页的人、要走审批流）。这时候不是从头另做，而是从**做好的 HTML 成品转**过去。

## 先想清楚：还原度 vs 可编辑，是有张力的

用户嘴上要的往往是「跟网页长一样，又能在 PowerPoint 里改」。这两件事其实冲突，先跟用户对清楚要哪头：

| 路子 | 还原度 | 可编辑 | 啥时候用 |
|---|---|---|---|
| **每页截图塞进 PPT** | 高（像素级一样） | 几乎不能改（就是张图） | 用户只是要个能放进 PPT 投影的版本，不打算改内容 |
| **重建成 PPT 原生元素** | 中高（字体/微间距会有差） | 真能改（文字框、形状、表格都是原生的） | 用户要在 PPT 里继续改字、换数据、套公司模板 |

用户既要高还原又要真可编辑时，**说清楚做不到两全**，让他选一头。多数「要可编辑」的真实诉求是后者——能改文字和数据，不在乎像素级一致。

## 可编辑路线：借官方 pptx skill 的原生能力

要可编辑，就调用官方 **pptx** skill，把 HTML 每页的内容重建成 PPT 原生元素，别去拼底层 XML。

大致这么走：

1. **先盘 HTML 的内容结构**：几页、每页有哪些块（标题、正文、卡片、表格、图片、二维码）。
2. **每页映射成 PPT 元素**：标题/正文 → 文本框；卡片网格 → 并排文本框或形状；对比表 → PPT 表格；图片/二维码 → 插入图片。
3. **颜色和字号对着 HTML 的 token 走**（`:root` 里那些 `--accent`/字号），让风格尽量贴近，但接受字体渲染、微间距上的差异。
4. **生成后自己看一眼**：每页有没有错位、文字有没有溢出文本框、表格列宽对不对。和截图自检一个道理——别生成完就交。

> 具体怎么用 pptx skill 建元素、它支持哪些操作，**以那个 skill 当下的文档为准**，别照背——它会更新。这里只定一件事：**可编辑 PPT 走 pptx skill 的原生能力重建，不要去拼 XML，也不要把整页截图当「可编辑」交差。**

## 截图路线：简单但是死的

用户只要个「能塞进 PPT 投影、不改内容」的版本，直接每页截图（[../scripts/shoot.mjs](../scripts/shoot.mjs) 逐页截）插进 PPT 就行。简单、像素级还原，但交付前**说清楚这是图、改不了字**，免得用户拿到发现动不了。
