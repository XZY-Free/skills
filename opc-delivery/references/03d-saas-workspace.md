# 03d — SaaS / 工作台类品类骨架

服务于"SaaS-工作台"主姿态的产品。用户主任务是**处理事务 / 推进任务流**: 工单、issue、任务、对话、客户、订单, 不是消费内容。

## 何时读

- 方案阶段产品姿态判断 = SaaS-工作台(主姿态)
- 不确定子类型属于协作平台 / 客服系统 / 项目管理 / 数据看板
- 写竞品调研 / 首屏主信号 / 升降级表需要品类默认参考

跳过场景: 主姿态不是 SaaS-工作台; 纯专业工具(IDE / 数据库客户端)独立处理。

## SaaS-工作台共通特征

### 主任务

处理事务 / 推进任务流。用户带着具体目标来(处理 5 个工单 / 推进 3 个 issue), 不是来"看看"。

### 默认 IA 骨架

| 层级 | 默认内容 |
|---|---|
| 首屏主信号 | "我现在该处理什么" — 待办列表 / 当前任务队列 / 我负责的 |
| 一级导航 | ≤ 5 项: 任务主体 / 队列管理 / 知识或资源 / 报表 / 设置 |
| 二级 | 筛选、视图切换、批量操作、详情面板 |
| 设置 | 角色 / 权限 / SLA / 通知 / 集成 / 计费 |

注意: SaaS-工作台是少数允许"5 项一级 nav"的姿态, 因为高频用户需要快速横切。但**不允许超过 5 项**。

### 升降级默认

| 能力 | 默认层级 | 理由 |
|---|---|---|
| 任务主列表(工单 / issue / 客户) | 高曝光 | 主任务承接 |
| 任务详情 | 高曝光 | 列表点入, 不独立设导航 |
| 队列管理 / 分派 | 高曝光 | 主管的主任务 |
| 知识库 / 资源库 | 中曝光 | 辅助主任务 |
| 报表 / 数据 | 中曝光(一级末位) | 主管用, 一线日常不用 |
| 筛选 / 视图切换 | 中曝光 | 列表顶部 |
| 批量操作 / 导出 | 仅上下文 | 选中后出现的 action |
| 评论 / 内部备注 | 仅上下文 | 详情页内 |
| 转人工 / 状态切换 | 仅上下文 | 详情页按钮 |
| 角色 / RBAC / 权限 | 低曝光 | 设置子项, 管理员偶尔 |
| SLA / 通知模板 | 低曝光 | 设置 |
| 计费 / 集成 webhook | 低曝光 | 设置 |
| 审计日志 | 低曝光 | 设置 > 安全 |
| 标签管理 / 自定义字段 | 低曝光 | 设置 |

### 共通首屏主信号写法

```
用户首屏第一眼看到:
- 主区(50-60% 视觉权重): <我负责的任务列表 / 待办队列 / 我的工单>
- 次区(20-30%): <筛选 / 视图切换 / 快速操作栏>
- 边缘: 导航 / 搜索 / 通知 / 头像

绝对不放在首屏的:
- Marketing hero / "欢迎使用 X" + CTA(高频工作台不需要 onboarding 抢主位)
- 看板风格的 4-8 个 KPI 卡(数据应在报表 tab, 不在主任务)
- 设置 / 集成 / 计费状态卡
```

特殊情况: 主管 / 管理员视角的首屏可以放数据看板(因为他们的主任务就是看数据决策), 但**应该是一种用户角色专属视图**, 不是所有人首屏。

## 子类型: 协作平台

例: Notion / Linear / Asana / Slack / 飞书 / Lark

### 主姿态特征
- 用户: 团队成员, 多角色
- 主任务: 推进项目 / 编辑文档 / 沟通协调
- 单次会话: 多次短回(打开 → 处理 → 关闭)

### 默认 IA

```
左侧栏: 工作区 / 项目列表 / 我的(任务/草稿/收件箱)
主体:   当前活跃项目 / 当前文档 / 当前对话
顶部:   搜索 / 通知 / 头像
```

### 升降级默认 (Notion-style)

| 能力 | 层级 |
|---|---|
| 文档主体 / 编辑器 | 高曝光 |
| 工作区 / 页面树 | 高曝光(左侧栏) |
| 最近 / 收藏 | 高曝光(左侧栏) |
| 搜索 | 高曝光(顶部, 常用) |
| 评论 / 协作 | 仅上下文 |
| 分享 / 权限 | 仅上下文(文档头部) |
| 模板 | 中曝光(新建时) |
| 团队设置 | 低曝光 |
| 集成 / API | 低曝光 |
| 计费 | 低曝光 |

### 反模式
- 首屏是"工作区欢迎页 + 模板墙", 用户进来不能直接干活
- 把"集成中心 / API 文档"做成一级导航位
- 文档编辑器小于 60% 屏宽(侧栏抢戏)

## 子类型: 项目管理

例: Linear / Jira / Asana / 飞书项目

### 主姿态特征
- 用户: 开发 / PM / 协作团队
- 主任务: 推进 issue / 看进度 / 分派
- 单次会话: 中等(查看 + 批量操作)

### 默认 IA

```
一级导航: 我的(my issues) / Active cycle / Backlog / Roadmap / 报表
主体:    issue 列表 / kanban / 时间线
顶部:    搜索 / 通知 / 创建 issue
```

### 升降级默认

| 能力 | 层级 |
|---|---|
| issue 列表 / kanban | 高曝光 |
| 我的 issue | 高曝光(一级) |
| Active cycle / Sprint | 高曝光 |
| Roadmap | 中曝光 |
| 报表 / Velocity | 中曝光 |
| 创建 issue | 高曝光(顶部按钮 + 快捷键) |
| 评论 / 关联 / 子任务 | 仅上下文 |
| 状态切换 / 分派 | 仅上下文(详情页) |
| 团队 / 项目设置 | 低曝光 |
| 工作流 / 自定义字段 | 低曝光 |
| 集成 | 低曝光 |

### 反模式
- 首屏没"我的 issue", 用户必须自己筛选
- "创建 issue"藏在二级菜单
- Roadmap 抢一级位(高频用户日常不看 Roadmap)

## 子类型: 客服 / 工单系统

例: Zendesk / Intercom / 美洽 / 微信客服

### 主姿态特征
- 用户: 客服一线 / 主管 / 质检
- 主任务: 接工单 → 处理 → 关闭
- 单次会话: 长(一线客服一上午都在处理工单)
- 用户角色显著不同(一线 vs 主管 vs 质检)

### 默认 IA

按角色不同 IA:

**一线客服**:
```
一级导航: 我的工单 / 待分派 / 队列 / 知识库 / 报表(看自己的)
主体:    当前工单详情 + 用户对话 + AI 建议 + 内部备注
固定:    左侧工单列表始终可见
```

**主管**:
```
一级导航: 队列 / 分派 / 报表 / 质检 / 设置
主体:    数据 / 趋势 / 异常预警
```

### 升降级默认 (一线视角)

| 能力 | 层级 |
|---|---|
| 工单列表 | 高曝光(左侧固定) |
| 工单详情 / 对话 | 高曝光(主体) |
| 智能建议回复 | 中曝光(侧栏) |
| 用户画像 | 中曝光(详情侧栏) |
| 知识库 | 中曝光(一级 tab + 详情内嵌) |
| 内部备注 | 仅上下文(详情底部) |
| 转人工 / 升级 | 仅上下文(详情按钮) |
| 标签 / 分类 | 仅上下文(详情顶部) |
| 报表(看自己绩效) | 低曝光(我之下) |

### 升降级默认 (主管视角)

| 能力 | 层级 |
|---|---|
| 队列概览 / 趋势 | 高曝光 |
| 分派规则 / SLA | 高曝光 |
| 报表 / 数据 | 高曝光 |
| 质检 | 高曝光 |
| 团队 / RBAC | 低曝光(设置) |
| 通知模板 | 低曝光(设置) |
| 计费 / 集成 | 低曝光 |

### 反模式
- 不区分角色, 给所有人同一首屏(一线被淹没在数据里, 主管找不到趋势)
- 转人工 / 状态切换做成独立页(应该是详情页操作)
- 设置 / 计费抢一级 nav(应在用户菜单)
- 一线客服首屏放"团队绩效看板"

## 子类型: 数据看板

例: Metabase / Grafana / Tableau / 神策 / DataDog

### 主姿态特征
- 用户: 数据分析 / 主管 / 运营
- 主任务: 看趋势 / 钻取异常 / 拖拉建表
- 注意: 这是 SaaS-工作台里**少数本身就是 dashboard** 的子类型, 反 dashboard 化承诺不适用

### 默认 IA

```
一级导航: 我的(已订阅 dashboard) / 探索 / 数据集 / 报表
主体:    当前 dashboard 主体 / 探索界面
顶部:    数据集切换 / 时间范围 / 筛选 / 分享
```

### 升降级默认

| 能力 | 层级 |
|---|---|
| Dashboard 主体 | 高曝光 |
| 我的 / 已订阅 dashboard 列表 | 高曝光 |
| 探索 / 新建查询 | 高曝光 |
| 时间范围 / 筛选 | 中曝光(顶部) |
| 数据集 / 表管理 | 中曝光 |
| 钻取 / 切片 | 仅上下文(图表上) |
| 导出 / 分享 / 订阅 | 仅上下文 |
| 告警规则 | 低曝光 |
| 用户 / 权限 / 数据源连接 | 低曝光(设置) |
| 计费 / 用量 | 低曝光 |

### 反 dashboard 化承诺(本子类型的特殊版本)

**dashboard 类首屏允许大量数据卡, 但仍要排序**:
- 指标按重要性分大小 / 位置, 不允许 12 个同等大小并排
- 必须有"主指标" + "次要指标"区分
- 默认时间范围 / 默认筛选要符合用户主任务

### 反模式
- 12 个 KPI 卡同等大小并排, 用户不知道哪个最重要
- 默认时间范围是"过去 30 天"但用户主任务是看实时(应改成"过去 1 小时")
- 把"数据源连接 / SQL 编辑器"做成一级 nav(应在设置或独立专业工具姿态)

## 品类反模式

跨子类型共通的反模式, 3C 验收时逐项扫:

- **首屏 marketing hero**: SaaS-工作台是高频工具, 用户进来要直接干活, 不要 onboarding 抢主位
- **一级导航超过 5 项**: 5 项硬上限。如果能力有 12 个, 必有 7 个该降到二级或设置
- **没有"我的 / 我负责的"主信号**: 用户进来不知道该处理什么 = 把工作台做成了知识库
- **设置 / 计费 / 集成进一级 nav**: 应在用户菜单或独立设置入口, 不抢主任务的位置
- **不区分用户角色**: 一线和主管同一首屏 = 谁都用不爽
- **批量操作藏得很深**: SaaS-工作台高频需要批量, 应在选中时立即出现
- **创建主对象的按钮不在顶部**: "新建工单 / 新建 issue / 新建客户"应是顶部高曝光按钮
- **详情页是独立路由而不是抽屉 / 主-从布局**: 列表-详情切换太慢 = 处理效率低
- **报表抢主区**: 一线视角下报表是中曝光; 主管视角才是高曝光

## 用法接入

### 方案阶段

读本文件 + [03b-productization.md](03b-productization.md) → 在 `.opc/solution/solution-design.md` 写:

1. **产品姿态判断**: 主姿态 = SaaS-工作台, 子类型 = 协作 / 项目管理 / 客服 / 数据看板
2. **竞品调研**: 选 2-3 个本子类型的成熟产品(本文件每节已列示例)
3. **首屏主信号**: 用本品类的模板; 多角色产品要分角色写
4. **能力升降级表**: 以本子类型的"升降级默认"为起点; 多角色时分角色给表

### 验证阶段

3C 对账时, 用本文件的"品类反模式"和"角色区分"做对照。多角色产品的 3C 应分角色截图分别对账。

### 注意

本文件的"升降级默认"是参考起点, 不是结论。多角色产品(如客服系统)应明确选定**首屏服务的主角色**, 其它角色作为子视图或角色切换。
