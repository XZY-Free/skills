每次用户给新任务进来,先做一次路由判断。**判错代价高**(一整轮工作可能要重做),
**问错也没那么贵**(一句话能澄清)—— 所以遇到模糊就问,但优先用选择题,
最后保留"自定义 / type something"入口。
路由完成后必须遵守 [delivery-contract.md](delivery-contract.md),不要把当前路径的
中间产物当最终交付物。

---

## 心智模型

| MCP | 定位 | 适合 |
|---|---|---|
| **Codify** | MasterGo 画布的"AI 工作台" | 在画布上**生产 / 修改 / 维护**设计 |
| **MasterGo Magic** | MasterGo 的"只读数据源" | 把已完成的设计**导出**变成代码 |

一句话区分:**"我在 MasterGo 里要做点什么" → Codify**;
**"我要把 MasterGo 上的东西拿出来" → Magic**。

## 关键词路由表

### 走 Codify 的信号

| 用户说 | 隐含意图 |
|---|---|
| "帮我设计一个 XX 页 / 落地页 / 后台" | 在画布上从零生成 |
| "在画布上加一个 / 改一个 / 替换一下 / 删掉" | 节点级编辑 |
| "调整颜色 / 字号 / 间距 / 布局 / 风格" | 画布上微调 |
| "优化一下设计 / 美化 / 重新设计这块" | 画布上迭代 |
| "用 XX 组件库做一版" | 走 design + useComponentLibrary |
| "看看当前文件有哪些页面"(在设计语境里) | 走 get_code_list / get_selection_code(配合插件操作引导) |
| "把这页复制一份 / 做个变体" | 走 agent_create_page / agent_create_component |
| "把这个组件同步成母版" | agent_sync_design / agent_create_component |

### 走 MasterGo Magic 的信号

| 用户说 | 隐含意图 |
|---|---|
| "还原 / 复刻 / 实现 / 跑出来 / 落地" | D2C 转代码 |
| "把设计稿做成网站 / Next.js / Vue / 前端项目" | 整套脚手架 + D2C |
| "D2C / DSL / getDsl / getD2c" | 直接走 Magic 工具 |
| "高保真还原 / 像素级 / 1:1 还原" | Magic 路径强约束补丁 |
| 给出 `https://mastergo.com/file/...?layer_id=...` 并说"还原" | Magic + layerId 解析 |
| "页面更新了 / 设计变了 / 重新拉一下设计"(在还原项目里) | Magic + update-flow.md |
| "把这页的代码拷出来"(已有 Magic 工程) | 单 frame D2C |

### 模糊或矛盾(必须问)

| 用户说 | 为什么模糊 |
|---|---|
| "帮我做个登录页" | 不知道是要在画布上设计,还是直接出代码 |
| "看看这个文件" | 看页面结构 vs 看代码结构 |
| "处理一下这个设计稿" | 处理含义太宽 |
| "把这个改一下"(指代不清) | 改画布 vs 改代码 |

**遇到模糊 → 直接发一句选择题澄清**,不要猜:

```
我先确认一下你想要的:

A. 在 MasterGo 画布上做设计(用 Codify MCP,成果在画布上)
B. 把 MasterGo 设计变成前端代码(用 MasterGo Magic MCP,成果在本地仓库里)
C. 自定义 / type something:你直接写想要的结果

你选哪一个?如果两个都要,也可以直接说顺序。
```

## 决策树(无脑跑这棵树)

```
1. 用户给了 mastergo URL 吗?
   ├── 是 → URL 带 "&layer_id=" 吗?
   │       ├── 是 → 用户语境是"实现/还原" 吗?
   │       │       ├── 是 → Magic
   │       │       └── 否 → 问澄清
   │       └── 否 → 让用户在画布选中后重发(无论哪条路都要 layerId)
   └── 否 → 进 2

2. 用户用了画布动词(设计/创建/修改/添加/删除/替换)吗?
   ├── 是 → Codify
   └── 否 → 进 3

3. 用户用了实现动词(还原/转代码/D2C/跑出来/复刻)吗?
   ├── 是 → Magic
   └── 否 → 进 4

4. 用户说"看看页面"类的查看请求?
   ├── 当前项目是 Magic 还原工程(有 src/design/*.html) → Magic 重拉 DSL
   ├── 当前项目跟 MasterGo 还没关联 → 问澄清
   └── 否则 → 倾向 Codify(因为查看也需要画布交互),但简短问一句

5. 上面都不匹配 → 直接问澄清问句
```

## 路由完成后

**告诉用户你选了哪条路**,简短一句:

> 走 **Codify**(画布设计)。下一步我先看你订阅了哪些团队组件库,选一个再开始生成。

> 走 **Magic**(D2C 还原)。下一步我先探嗅一下你项目里现有的前端框架。

让用户随时可以纠正路由(`不对,我是想 XX`),不要默默改方向。

同时确认真实交付物:
- Codify = MasterGo 画布写入并验证;
- Magic = 本地前端实现并验证;
- update = 增量变更应用并复验;
- setup = 当前宿主配置写入并重启/连通验证。

如果路由到 Codify 设计,下一步必须进入 [design-scope.md](design-scope.md) 形成
需求覆盖 brief;不要只凭关键词决定页面数量或设计范围。

缺对应能力时进入阻塞流程,不要换成交付文档、prompt、截图或分析报告。

## 切换路由的情况

- **设计完想还原**(常见):Codify 路径走完 → 用户说"现在把它变成代码" → 切到 Magic;
- **还原中需要回画布微调**(偶尔):Magic 路径走到一半发现设计有问题 → 用户说"我去改一下设计" → 暂停 Magic,等用户改完回阶段 4(update-flow);
- **频繁来回切**(罕见但合法):两个 MCP 同时在线就可以,不需要重装。

切换时**显式确认一次**:"我现在切到 X MCP,继续做 Y,确认?" 避免静默切换。
