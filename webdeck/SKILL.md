# webdeck

用 HTML 做演示稿。培训、汇报、产品介绍、对外分享——这类要往屏幕上投、要讲给人听的页面，都走它。

主力交付是**单文件 HTML**：一个 `.html` 双击就能放映，离线也行，按投屏比例排版。有人现场讲的，再配一份**讲师讲稿**（单独的 `.md`，逐页对应）。要 PPT 的时候，从做好的 HTML **转**成可编辑的 `.pptx`（借官方 pptx skill），而不是从头另做一份。

## 最在乎的一件事：别做出 AI 味

这是 webdeck 和官方 pptx、frontend-design 最大的不一样。那些工具能把页面生成出来，但生成的东西常常一眼就能看出是 AI 堆的：话说得太满、句子工整得像一个模子刻的、视觉上堆装饰。

webdeck 的功夫几乎全花在「不像 AI 做的」上面。一句话概括这股劲儿：

> **少替听众安排，别居高临下，能删就别凑。**

AI 味的根都是「过度」——话说太满（对仗、套话）、姿态摆太高（说教、导览解说）、装饰堆太多（炫技）。把这三种「过度」收住，味儿就淡了。

展开的判断，怎么认出 AI 味、怎么收，在 [references/anti-ai-flavor.md](references/anti-ai-flavor.md)。每次写文案、调版式都对着那个感觉走。**这是 webdeck 的主心骨**——它讲的是怎么养出那个语感，不是一张钉死的清单去背。

> ⚠️ 连这份 SKILL.md 自己也按这个标准写——你要是发现哪句话端着、哪段在凑工整，那就是没做到位，改掉。

## 大致怎么走

不是死步骤，按当下情况来。但有一条方向别违背：**先把内容和语气聊透，再动手做页面**，别一上来就写 HTML。页面是壳，里面讲什么、用什么口气讲，才是难的部分。

1. **先聊内容和语气。** 主题不熟就先查（直接 `curl` 抓官方文档/资料，别凭印象编）。把要讲几块、每块讲什么、对谁讲、什么口气，跟用户对清楚。这一步省下来，后面返工更多。
2. **长相现设计，别套模板。** 配色、版式、风格每次按这次的内容重新设计，交给 frontend-design 那套审美来驱动。**不要套一个固定模板**——你做十份长一个样，别人一眼就认出是同一个模子，那本身就是 AI 味。要给用户挑风格，做成真实 HTML 让他看（见下面那条）。
3. **搭页面。** 翻页、字体、离线、投屏尺寸这些枯燥又易错的「引擎」用现成脚手架，省得每次重写；内容按「别 AI 味」的劲儿写。脚手架和怎么用，在 [references/deck-engine.md](references/deck-engine.md)。
4. **（有人现场讲就配讲稿）** 培训、汇报这种有人照着念的，页面之外再配一份讲稿——单独的 `.md`，逐页对应。纯自己看的（产品介绍、对外分享）就不必。口播稿的去 AI 味比页面文案还狠一层（最容易栽在「润色而非重构」上），还有「先写几页让用户认可声音、再统一全篇」的校准法，在 [references/talk-track.md](references/talk-track.md)。
5. **截图自检。** 代码对不等于视觉对。用 Playwright 按投屏比例（1440×810）截下来自己看一眼，排版崩没崩、有没有溢出。顺手把改动留下的孤儿 CSS 清掉。做法在 [references/self-check-and-deploy.md](references/self-check-and-deploy.md)。
6. **（可选）部署。** 要上线就改本地→传服务器→实测验证，通用做法在 [references/self-check-and-deploy.md](references/self-check-and-deploy.md)。**具体哪台服务器、什么路径，不写在 skill 里**，那是各项目自己的事，记到项目记忆里。
7. **（可选）转 PPT。** 用户要可编辑的 PPT，就从做好的 HTML 成品转，借官方 pptx skill 的原生能力把每页重建成 PPT 元素。怎么权衡「还原度」和「可编辑」，在 [references/html-to-pptx.md](references/html-to-pptx.md)。

## 一条贯穿始终的做法：让人看实物，别用嘴描述

凡是关于长相的选择——配色、版式、某页怎么排——**直接做成真实 HTML 让用户看，不要用文字或 ASCII 框图描述**。

「清爽蓝调企业风」这种话，用户脑子里和你脑子里想的根本不是一个东西。做两三个真页面并排放出来，他扫一眼就知道选哪个。视觉的事看实物最快，这一条能省掉大量来回猜。

## 什么时候用它

用户说这些，就该用 webdeck（哪怕没明说「幻灯片」）：

- 「做个 PPT」「做个演示页」「做个网页」（在培训/汇报/分享/介绍的语境下）
- 「把这份内容做成幻灯片 / 演示稿」
- 「做个 XX 培训的页面」「做个产品介绍页」「做个汇报材料」
- 已经有一份这样的 HTML，要改文案 / 改版式 / 去 AI 味 / 加页

## 什么时候别用

这些不是「讲给人听的演示页」，别套 webdeck：

- 写 web 应用、后台、管理系统、单个前端组件 → 那是 opc-delivery / 普通前端活
- 纯数据可视化 dashboard、报表系统
- 修网页 bug、调某个现有站点的功能
- 纯 Figma 设计、纯截图处理

「做个网页」这种话两边都沾——按语境判断：是要**讲给人听、往屏幕上投的叙事页**，才是 webdeck；是要**有人用、能点能操作的应用**，那不是。
